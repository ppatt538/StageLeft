ROLE
You are a senior full-stack engineer. Build a production-quality MVP web app called **Daydesk** on Replit. Plan briefly (5–8 bullets), then implement. Prefer working software over perfect abstraction.

GOAL (1 sentence)
Daydesk is an AI-managed temporal desktop: the user chats (or drops a link/image) at the bottom; the AI creates typed “objects” (cards) on a canvas; time buckets are Today / This Week / Archive; search finds everything. Desktop = spatial card canvas. Mobile = simplified stacked blocks that expand.

WHO IT’S FOR
Single primary user (me) for now — personal capture desk for tasks, reminders, notes, links, and image-derived items. Must work great on desktop and phone in the same responsive web app.

SUCCESS LOOKS LIKE
When done I can: open the app → see seeded Today cards → type a message in chat → an object appears on Today → check off checklist items → switch Week/Archive tabs → search finds objects → resize to phone width and use expandable blocks → refresh and data persists. AI can be a real OpenAI-compatible call if OPENAI_API_KEY exists, otherwise a solid deterministic mock parser so the app is fully demoable offline.

DATA MODEL (implement exactly)
────────────────────────────────────────
Table: objects
- id: text primary key (ulid or uuid)
- type: text enum — checklist | note | reminder | event | link | media | poster
- title: text not null
- bucket: text enum — today | week | archive | pinned
- status: text enum — active | done | snoozed | discarded  (default active)
- priority: integer default 0
- tags: JSON array of strings default []
- layout: JSON { x:number, y:number, w:number, h:number, z:number } nullable (desktop positions; mobile ignores)
- payload: JSON not null (type-specific)
- source: JSON { kind: chat|image|url|voice|seed, messageId?:string, rawText?:string, mediaIds?:string[] }
- search_text: text not null  (flattened plain text for search)
- ai: JSON { confidence?:number, rationale?:string, needsReview?:boolean } nullable
- links: JSON array default []  // [{ to, rel }] optional for MVP
- snooze_until: text ISO nullable
- created_at: text ISO
- updated_at: text ISO
- last_touched_at: text ISO
- completed_at: text ISO nullable

payload shapes:
- checklist: { items: [{ id, text, done:boolean }] }
- note: { markdown: string }
- reminder: { when: ISO string, end?: ISO, location?: string, url?: string }
- event: same as reminder + optional { allDay?: boolean }
- link: { url, title?, summary?, favicon? }
- media | poster: { imageUrl?, ocrText?, extracted?: { what?, who?, when?, where? }, enrichment?: object }

Table: messages (chat log)
- id, role (user|assistant|system), content text, created_at
- optional meta JSON { ops?: AiOp[] }

Table: media (optional but preferred)
- id, filename, mime, url/path, created_at

Indexes: bucket, status, updated_at; FTS or LIKE search on search_text + title for MVP (SQLite FTS5 if straightforward, else LOWER(search_text) LIKE).

────────────────────────────────────────
AI OPS PROTOCOL (critical)
────────────────────────────────────────
The model does NOT freeform mutate the DB. Chat endpoint:
1) Accept user text + optional attachment metadata
2) Build messages with system prompt
3) Model must return ONLY valid JSON:

{
  "assistantMessage": "short human confirmation",
  "ops": [
    {
      "op": "create_object" | "update_object" | "complete_item" | "move_bucket" | "pin" | "set_status",
      ...op-specific fields
    }
  ]
}

create_object fields: type, title, bucket?, payload, tags?, priority?, ai?
update_object: id, patch { title?, payload?, tags?, ... }
complete_item: objectId, itemId, done
move_bucket: id, bucket
pin: id  (sets bucket pinned)
set_status: id, status

Server validates ops, applies in a transaction, rebuilds search_text, returns { message, objectsChanged }.

System prompt rules for the model:
- Prefer one primary object per user message unless clearly multiple intents.
- "things to do today: a, b, c" → checklist on today.
- ISO dates when user mentions times; use USER_TZ for relative dates (today, tomorrow, next Friday).
- If image/OCR provided, prefer poster/media + reminder/event if a date is found; set needsReview true if uncertain.
- Never delete; use discarded or archive.
- Keep assistantMessage ≤ 2 sentences.
- If unclear, return ops:[] and ask one clarification in assistantMessage.

MOCK AI (required when no API key):
Parse heuristically:
- If text matches task list patterns (commas, newlines, "todo", "today") → checklist
- If URL detected → link object (try fetch title if easy, else url as title)
- If contains "remind" or clear datetime → reminder
- Else → note
Always return proper ops JSON.

────────────────────────────────────────
TIME / ROLLOVER RULES
────────────────────────────────────────
Implement POST /api/rollover (also run on server start once per local calendar day and on GET /api/objects if last_rollover_date < today in USER_TZ):

Rules:
1) pinned: never auto-move
2) status done → bucket archive (if not pinned); set completed_at if missing
3) incomplete objects in today with created/last_touched before today's local date → move to week (carry forward; keep checklist progress)
4) incomplete week items with last_touched_at older than 7 local days → archive with status active still OR status snoozed optional; use status "active" and bucket archive is enough; optionally tag "stale"
5) reminders/events with when < start of today and still active → stay visible in today or week if overdue (show overdue badge in UI); do not hide

Do NOT hard-delete on clear. Today tab is a filter on bucket=today (and overdue smart bits if easy).

API ROUTES
────────────────────────────────────────
- GET /api/health
- GET /api/objects?bucket=today|week|archive|pinned|all&q=
- GET /api/objects/:id
- PATCH /api/objects/:id   (manual edits: title, payload, layout, bucket, status, priority, tags)
- DELETE /api/objects/:id  (soft: status discarded)
- POST /api/chat   body: { message: string, mediaIds?: string[] }
- POST /api/upload  multipart image
- POST /api/rollover
- GET /api/messages?limit=50

Validate inputs. Return JSON errors { error: string }.
